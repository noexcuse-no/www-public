# Review-Core Rollout — live links to unpublished pages (issue 260921-01)

> Created: 2026-09-21
> Status: Done
> Fix branch: `fix/rollout-links-to-unpublished`

## Problem / Goal

The live site (https://noexcuse.no/ledelse-60-2/) showed clickable links to
pages excluded by the review-core rollout — `prune:unpublished` removes such
links only in the local pipeline, while GitHub Pages' native build ships the
published source as-is, so the pruner's guarantees never reached production.
Goal: no published page source may contain a link to an unpublished internal
page, so production output equals the locally-pruned expectation.

## Root Cause

`prune:unpublished` is a post-build gate enforced locally via `ci:local`
(`_site` built in-place). The production site is built natively by GitHub
Pages from the same source — the pruning step is not part of that pipeline, so
any source link to an unpublished page leaks into production. The rollout had
de-linked the homepage §8 "Les mer" links but missed three other kept pages.

## Scope

published pages that still referenced unpublished pages:

- `_pages/ledelse-60-2.md` — 24 wrappers removed: GRC paragraph (`/grc/`),
  step tails (`/intervju/`, `/rapport/` "Les mer →"), 12 signal-card links

## Lessons Learned

- The frame-cards/«Relaterte perspektiver» markdown links on `ledelse-60-2.md`
  render as raw text on the live page (the `sample-report-preview.html` include
  breaks kramdown parsing of subsequent markdown), so neither `check:links` nor
  the pruner flags them — but they are still source links to unpublished pages
  and must be de-linked at the source, not judged by rendered output.
- The pruner is a dependency-safety mechanism for the local pipeline, never a
  production guarantee: source hygiene is the contract that holds on GitHub
  Pages' native build.
