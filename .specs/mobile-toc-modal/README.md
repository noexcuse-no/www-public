# Mobile TOC — Modal Overlay (R34)

> **Status:** Planning
> **Created:** 2026-06-13
> **Backlog item:** R34

## Problem

On wide screens (≥1200px), the article TOC lives in the left `.article-pager` sidebar with scroll-spy highlighting. On mobile/tablet (<1200px), the entire pager is hidden (`display: none`), so there is no TOC at all. The old `<details class="toc-collapsible">` approach was removed because it broke the scroll-spy JS and was structurally incompatible with the JS-driven TOC generation.

Visitors on mobile have no way to navigate between sections of long articles without manual scrolling.

## Solution

A floating "Innholdsfortegnelse" button on the article page (mobile/tablet only) that opens the TOC as a **modal overlay** — not an inline collapsible. The modal contains the same TOC items as the desktop sidebar, generated by the existing JS, with the same scroll-spy highlighting.

## UX Flow

```
[Innholdsfortegnelse ☰]  ← floating button, sticky at top-right of article body on mobile
        │
        ▼ tap
┌──────────────────────────────┐
│  Innholdsfortegnelse    [X] │
│                              │
│  ○ H2 heading 1        ← active
│    ○ H3 subheading           │
│  ○ H2 heading 2              │
│  ...                         │
│                              │
│  [Lukk]                      │
└──────────────────────────────┘
        │
        ▼ tap item
  → Smooth-scroll to section
  → Modal closes
```

## Requirements

### Button
- Visible only on screens < 1200px (same breakpoint where `.article-pager` hides)
- Fixed/sticky position at top-right of article body or as a floating pill
- Label: "Innholdsfortegnelse" with a list/bullet icon
- Uses existing `.cta` or `.cta--secondary` button styling
- Min 44×44px touch target
- Hidden on articles with no TOC items (0 headings)

### Modal
- Full-screen overlay on mobile (< 600px), centered modal on tablet (600–1199px)
- Same visual pattern as existing modals: dark overlay (`--overlay-light`), white card (`--box-background-light`), `--radius-xl`
- Close button (X) top-right + "Lukk" button at bottom
- Focus trap: Tab cycles within modal, Escape closes, tapping overlay closes
- Body scroll lock when modal is open

### TOC Content
- Same items as desktop sidebar — generated by `sidebar.js` from `<h2>`/`<h3>` in `.article-body`
- Scroll-spy highlighting works inside the modal (active section is highlighted when modal opens)
- Clicking an item: smooth-scroll to section + close modal
- If modal is open while scrolling, the active highlight updates in real-time

### Implementation

**HTML**: Add a container element in `_layouts/article.html`:

```html
<button class="toc-mobile-toggle cta cta--secondary" aria-label="Åpne innholdsfortegnelse" hidden>
  <span class="toc-mobile-toggle-icon" aria-hidden="true">☰</span>
  Innholdsfortegnelse
</button>

<div class="toc-mobile-overlay" role="dialog" aria-modal="true" aria-label="Innholdsfortegnelse" hidden>
  <div class="toc-mobile-modal">
    <div class="toc-mobile-header">
      <h2>Innholdsfortegnelse</h2>
      <button class="toc-mobile-close" aria-label="Lukk">✕</button>
    </div>
    <nav class="js-toc-list toc-list" aria-label="Innholdsfortegnelse"></nav>
    <button class="cta cta--secondary toc-mobile-close-bottom">Lukk</button>
  </div>
</div>
```

**JS** (modify `sidebar.js`):
- After building the desktop TOC items, clone them into the mobile modal container (same pattern as the old `.js-toc-collapsible-list` code path — update target selector to `.toc-mobile-overlay .js-toc-list`)
- Add click handler for toggle button (show modal, lock body scroll)
- Add click handlers for close (X, Lukk button, overlay click, Escape)
- Focus management: trap focus in modal, return focus to toggle button on close
- Re-use same scroll-spy update for the modal TOC items

**CSS**: New file or section for `.toc-mobile-toggle`, `.toc-mobile-overlay`, `.toc-mobile-modal`.
