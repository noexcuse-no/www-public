# Homepage hero mobile overflow

> Created: 2026-09-28
> Status: Done

## Problem / Goal

At viewports ≤767px the homepage hero overflows horizontally: measured at 390px, `scrollWidth` is 540 vs `clientWidth` 390 — every hero child except the headline (capped by its own `max-width: 15ch`) renders 520px wide, producing 150px of horizontal scroll on phones.

Root cause: the mobile rule `.home-hero__media img { max-width: 520px }` gives the hero image a 520px min-content contribution. The image is a direct child of `.home-hero__media` (no `.media-scene` wrapper, no `width: 100%`), and the mobile hero grid track uses plain `1fr`, whose implicit minimum is `auto`. The track grows to the image's 520px min-content and drags the whole single-column track — including the text column — to 520px. The desktop grid avoids this with `minmax(0, …)` tracks (minimum 0).

## Scope

- `assets/css/components/home.css`, `@media (max-width: 767px)` hero block only
- No markup changes; no desktop or tablet geometry changes

## Implementation

- Mobile track: `grid-template-columns: minmax(0, 1fr)` — same blowout-proof idiom the desktop grid already uses
- Mobile image cap: `max-width: min(520px, 100%)` — keeps the 520px design cap where room allows, never exceeds the container

## Acceptance Criteria

- [x] At 390px: no horizontal overflow (`scrollWidth === clientWidth`); hero text column and image ≤ container width
- [x] At 768px and 1440px: hero geometry unchanged from pre-fix build
- [x] Verified in both light and dark themes
- [x] lint:css clean; ci:local 12/13 (known pre-existing lint gate documented)
